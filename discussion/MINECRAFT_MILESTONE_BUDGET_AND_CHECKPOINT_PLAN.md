> 日期：2026-08-12  
> 用途：规划 DreamerV3 Minecraft 后续训练，不授权自动启动长训练。  
> 当前基线：EXP-0012，`size50m/ratio32/seed0/100K`；候选执行配置为同机 `envs=4`。

## 1. 当前结论

EXP-0012 已在真实 MineRL/Malmo 环境中完成 100K environment steps：

- 独立评测稳定获得 `log` 和 `planks`：`3/3` 回合；

## 3. 当前设备的成本阶梯

按 `envs=4` 的短探针模型估计：启动成本约 `183 s`，稳态 `53.84 steps/s`。从原始 100K
checkpoint 连续续训的理想时间为：

| 绝对终点 | 新增步数 | 预计训练墙钟 | 主要判断 |
|---:|---:|---:|---|
| 200K | 100K | 约 34 min | 续训完整性与 L1 保持 |
| 300K | 200K | 约 65 min | 木镐开始进入可能区间 |
| 500K | 400K | 约 2.1 h | 木镐/圆石的首选性价比点 |
| 1M | 900K | 约 4.7 h | 木镐、圆石、石镐是否形成 |
| 2M | 1.9M | 约 9.9 h | 石器链是否稳定并接触铁矿 |
| 5M | 4.9M | 约 25.3 h | 熔炉、铁锭阶段候选 |
| 10M | 9.9M | 约 51.2 h | 铁镐阶段候选，不是近期首选 |
| 50M | 49.9M | 约 10.7 days | 仅为吞吐外推，不建议当前追钻石 |

长程训练可能受 replay 增长、CPU 波动、保存开销和环境异常影响，以上不是工期承诺。分段运行还会
重复支付启动/JIT 成本。完整 Minecraft 评测也可能接近一小时，因此不能在每个小节点都评测。

## 4. 性价比目标

### 第一优先级：木镐到石镐

- 预算：500K--1M；
- 成本：约 2--5 小时；
- 意义：从“会砍树和基础合成”推进到“会制造工具并采石”，首次形成有前后依赖的技能链；
- 展示价值：明显高于只展示工作台，同时成本仍可控。

### 第二优先级：熔炉和铁锭

- 预算：先到 2M，再视证据放行 5M；
- 成本：约 10--25 小时；
- 意义：要求采石、造石镐、找铁矿、造熔炉和冶炼，能展示更长的技术树规划；
- 这是比钻石更现实、又比木器阶段更有区分度的中期目标。

### 第三优先级：铁镐

- 参考区间：约 5M--10M；
- 只有 5M 已重复出现熔炉和铁锭时才值得放行；
- 达到铁镐已能说明长程技能组合，但预计至少两天级墙钟。

### 暂不以钻石为目标

- 公开曲线的钻石中位出现点约 51M；
- 当前吞吐下约为 11 天量级，且本地只有 50M 模型，不能假定复现论文的 200M 模型结果；
- 钻石适合作为长期上限，不是当前日报、PPT 或知识星球素材的性价比首选。

## 5. 阶段性训练与放行门

训练可以依据阶段结果决定是否继续，但应在运行前固定判断门，避免看到偶然正例后不断追加预算。

### 200K 门

- 必做：训练完整性、旧/new stepid、checkpoint、replay、有限损失和资源检查；
- 做三回合独立评测，确认 L1 是否保持；
- 200K 没有木镐不是失败，因为公开曲线中木镐通常更晚出现。

### 500K 门

- 保存 300K 中间快照，但不强制完整评测；
- 训练到 500K 后统计新增 replay 中每个里程碑的成功 episode 数和首次/末次出现位置；
- 若木镐或圆石出现，做独立评测并优先放行 1M；
- 若未出现但 L1 仍稳定，可再放行一次 1M，因为木镐中位首次出现约为 637K；
- 若 L1 退化、训练异常或动作链证据矛盾，停止扩步并诊断。

### 1M 门

- 若木镐、圆石或石镐在多个训练 episode 中重复出现，或终点评测可以复现，放行 2M；
- 若只出现一次，记为探索事件，不称为掌握，可依据频率趋势决定是否做一次有界 2M 验证；
- 若新增 900K 经验仍完全没有木镐，应停止堆步数，检查动作空间、合成动作、探索和奖励链。

### 2M 门

- 若石镐或铁矿重复出现，且 L1/L2 没有退化，可放行 5M；
- 若仍停留在木器阶段，5M 的信息收益较低，应先做失败轨迹和 replay 转移分析。

### 5M 门

- 若熔炉或铁锭已重复出现，可把本阶段视为高价值成果并优先停止、评测和整理材料；
- 若铁锭已稳定而铁镐尚未出现，可在开始下一段前预注册 7.5M 或 10M 的单一上限；
- “差一点”必须由 inventory 链证据定义，例如多个 episode 已到铁锭，而不是凭 loss 或视频印象判断；
- 禁止在运行中把上限从 5M 连续改到 6M、7M、8M，直到偶然成功。

## 6. 如何判断“达到目的”

使用三级证据，避免把一次偶然探索误认为模型能力：

1. **Encountered**：训练 replay 中至少一次出现该物品，只能说明探索到过；
2. **Repeated**：至少两个独立训练 episode 出现，说明行为链开始重复；
3. **Retained**：冻结 checkpoint 的独立新世界评测中复现，才支持终点策略保留该能力。

日报可以完整报告三个层级。是否追加预算主要依据 Repeated 和 Retained；Encountered 适合作为下一档
预算的弱放行信号，但不能单独承担“学会”的结论。

## 7. 快照与恢复设计

### 7.1 三类保存

1. **运行恢复 checkpoint**：每 10--15 分钟保存最近状态，用于进程或机器异常后的恢复；
2. **阶段完整快照**：在 200K、500K、1M、2M、5M 等节点冻结 agent、optimizer、step、replay、
   config、代码 commit、metrics 和 SHA256；
3. **展示 checkpoint**：仅永久保留关键阶段的 agent checkpoint、评测 JSON 和视频，降低长期存储成本。

默认 `save_every` 按墙钟触发，只能保证最近状态可恢复，不能替代永久阶段快照。关键节点必须额外
冻结，且不能边写边复制 live checkpoint/replay。

### 7.2 已验证的恢复能力

服务器 EXP-0015 已验证：

- EXP-0012 原始 100K checkpoint/replay 哈希保持不变；
- 隔离 CoW 副本保留全部 100K 旧 transition；
- 在 `envs=2` 下精确新增 5040 条无重复 transition，并结束于 step 105040；
- agent、optimizer、step、replay 和训练指标能够一起恢复。

因此在 5M 停止并不会前功尽弃，可以从完整快照继续到 7.5M 或 10M。恢复时 Minecraft 环境会开启
新世界，未结束 episode 的现场状态不会延续；损失的是当前单局进度，而不是已更新的模型参数和已保存
的 replay 经验。

### 7.3 存储策略

- 100K 时 agent checkpoint 约 `575 MB`，replay 约 `1.09 GB`；replay 会随步数增长，5M 容量可能
  达到数十 GB；
- 同一 XFS 数据盘优先使用已验证的 reflink/CoW 创建阶段副本，并检查 inode 隔离和源树哈希；
- 只对 200K、500K、1M、2M、5M 保留完整恢复快照；300K 等中间点可只保留 agent checkpoint
  和分析摘要，除非它承担正式比较；
- 每次恢复前后核对源哈希、最终 step、旧 transition 保留率、新 transition 唯一性和 replay 完整性。

## 8. 当前建议

1. 先完成已预注册的 EXP-0017：100K -> 200K，`envs=4`，三回合独立评测；
2. 若完整性和 L1 保持通过，下一次正式目标直接定为 500K，在 300K 留中间快照；
3. 500K 后根据木镐/圆石的 Encountered、Repeated、Retained 三层证据决定是否到 1M；
4. 只有 1M 形成石器链，才考虑 2M；只有 2M 接触铁矿，才考虑 5M；
5. 近期成果目标优先选择木镐/石镐，其次熔炉/铁锭，不追钻石。
